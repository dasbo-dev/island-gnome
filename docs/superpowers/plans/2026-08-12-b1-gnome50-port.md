# B1 GNOME 46→50 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retarget the typings to GNOME Shell 50, close the ten remaining typecheck errors, and declare `shell-version: ["46","47","48","49","50"]` backed by runtime validation on all five Shells.

**Architecture:** The port is type-level only — no emitted JavaScript changes behaviour. Typings pin to one `@girs` generation (50); the declared range rests on runtime validation instead. Two of the ten errors' root causes are closed by a deletion (a dead `declare module` augmentation) and a constant rename (`true` → `PopupAnimation.SLIDE`); the remaining six are closed by re-exporting four registered classes through a cast whose signature is *derived* from the implementation class, so it cannot drift.

**Tech Stack:** TypeScript 5 (`tsc --noEmit`, three projects), esbuild via `build.mjs`, Vitest 2, GJS / GNOME Shell, `@girs/*` typings, libvirt + podman for validation.

## Global Constraints

## Task 1: Retarget the typings to GNOME 50

**Files:**
- Modify: `package.json` (`devDependencies["@girs/gnome-shell"]`, the whole `overrides` block)
- Modify: `package-lock.json` (regenerated)

**Interfaces:**
- Consumes: nothing.
- Produces: a `node_modules` tree where `@girs/gnome-shell` is `50.0.4` and exactly one copy of each `@girs/*` package is installed. Every later task's error counts are meaningless without this.

**Why the two passes.** The `overrides` block is a **deduplicator, not a version pin**. ## Task 4: registerClass constructor arguments (D1)

**Files:**
- Create: `src/shell/typeAssert.ts`
- Modify: `src/shell/popupHeader.ts` (`PopupHeader`, `EmptyRow`)
- Modify: `src/shell/sessionRow.ts` (`SessionRow`)
- Modify: `src/shell/island.ts` (`Island`)

**Interfaces:**
- Consumes: Task 1's retargeted tree; Task 3's edits to `island.ts`.
- Produces:
  - `src/shell/typeAssert.ts` exports two types: `Equals<X, Y>` (resolves to `true` or `false`) and `Assert<T extends true>` (a compile error unless `T` is `true`). Both are type-only; the module emits no runtime code.
  - `PopupHeader`, `EmptyRow`, `SessionRow`, `Island` keep the **same export names, same constructor signatures and same instance types** as before. No call site in `extension.ts` or `island.ts` changes. `InstanceType<typeof SessionRow>` and friends keep working exactly as they do today.

**The problem.** `@girs/gobject-2.0@4.1.0` types the registered constructor as:

```ts
new (...args: P extends Init ? Parameters<P['_init']> : [void])
```

Arguments come from `_init`, not from the TypeScript `constructor`. Four classes declare a constructor with non-GObject parameters and are therefore mistyped:

| Class | File | Arity |
|---|---|---|
| `Island` | `src/shell/island.ts:105` | 4 |
| `SessionRow` | `src/shell/sessionRow.ts:63` | 5 |
| `PopupHeader` | `src/shell/popupHeader.ts:23` | 2 |
| `EmptyRow` | `src/shell/popupHeader.ts:71` | 1 |

**Do not try a `declare _init` shim.** The base classes declare `_init` concretely (`_init(params?: Partial<ConstructorProps>): void` on `PopupBaseMenuItem`, three overloads on `PanelMenu.Button`), so a narrowed override fails `TS2416` and the total rises 13 → 14. This was tried and measured.

**The pattern.** Keep the class expression *named* and assign it to a `const`, so its constructor can be read back with `ConstructorParameters`:

```ts
const PopupHeaderImpl = class PopupHeader extends PopupMenu.PopupBaseMenuItem {
  /* body completely unchanged */
}

const _PopupHeader = GObject.registerClass(PopupHeaderImpl)

export const PopupHeader = _PopupHeader as unknown as new (
  ...args: ConstructorParameters<typeof PopupHeaderImpl>
) => InstanceType<typeof _PopupHeader>
```

Three details, each load-bearing:

1. **The class expression keeps its original name** (`class PopupHeader`, assigned to `PopupHeaderImpl`). GJS derives the GType name from the class's name. Renaming the class to `PopupHeaderImpl` would silently rename its GType; a named class expression assigned to a differently-named const changes nothing at runtime.
2. **`ConstructorParameters<typeof PopupHeaderImpl>`**, not a hand-written signature. Change a constructor argument and the exported type follows on its own. The drift report's main objection to this whole approach was the hand-maintenance tax; this is how it is paid off.
3. **`InstanceType<typeof _PopupHeader>`** preserves the subclass's own methods, so call sites keep their typing.

The cast is still `as unknown as` and still suppresses checking. What it asserts is now only "registration preserves the constructor" — true, and it does not rot.

**The guard.** The derived signature makes `ConstructorParameters` on the export tautological, so asserting *that* would prove nothing. The substantive claim is that registration preserves the **instance type**, and that one does go through `RegisteredClass`:

```ts
type _PopupHeaderKeepsImpl = Assert<
  Equals<InstanceType<typeof PopupHeader> extends InstanceType<typeof PopupHeaderImpl> ? true : false, true>
>
```

If a future `@girs` changes `RegisteredClass` so the registered instance no longer carries the implementation's members, this fails to compile and someone reads this section — instead of the cast continuing to lie.

**Fallback.** The pattern assumes `GObject.registerClass()` accepts a `const`-held named class expression as cleanly as the inline argument it gets today. This is expected to hold. If it does not, fall back to the hand-written signature already verified on `popupHeader.ts` (it took the count 13 → 11):

```ts
export const PopupHeader = _PopupHeader as unknown as new (
  base: string,
  cb: PopupHeaderCallbacks
) => InstanceType<typeof _PopupHeader>
```

Record in the commit message that the derived form was tried and why it failed. **Do not invent a third pattern.**

```ts
 * Compile-time assertions, used by the registered classes in this directory.
 *
 * `GObject.registerClass()` returns a constructor whose parameters
 * @girs/gobject-2.0 derives from `_init` rather than from the TypeScript
 * `constructor`, so each registered class is re-exported through an
 * `as unknown as` cast that restores the real signature. The cast suppresses
 * checking; `Assert` puts a compile error back where the checking used to be.
 *
 * Nothing here emits any runtime code.
 */

/**
 * True only when X and Y are the same type — including when one is `any` and
 * the other is not, which a bare conditional would let through. The deferred
 *-conditional trick is the standard way to get invariant equality out of
 * TypeScript.
 */
export type Equals<X, Y> = (<T>() => T extends X ? 1 : 2) extends <T>() => T extends Y ? 1 : 2
  ? true
  : false

/** A compile error unless `T` resolves to `true`. */
export type Assert<T extends true> = T
```
